# 二开改动实施计划（2026-11-11）

> 承接《调研与二开计划》。本文是「改代码 → 验收 → 部署」的完整落地计划。
> 品牌与包名已确认：App 显示名 **AgentPort**，applicationId **`com.xcoder.agentport`**。
> **中继服务器域名当前以 `dsh.r2049.cn` 为占位值**（尚未正式部署，部署时全局替换为真实域名，见第六节）。

## 一、目标（为什么）

1. **走自己的中转**：远程连接走 DSH Remote 协议（通道 A），中继服务器换成自己部署、自己域名的服务器，不走上游 `dsh.r2049.cn`。
2. **换皮**：用户可见的开源项目痕迹（名称、包名、图标、吉祥物、文案）全部换成自己的品牌，只改用户能看到的，内部代码标识不动。
3. **隐藏配套功能**：更新 / 统计 / 论坛 / 插件市场 / 托管分享，这些依赖上游 dshtui.com 的入口先隐藏，保留代码。
4. **留痕**：每轮改动落文档。

## 二、范围界定（改 / 不改）

**改的（全部在手机 App 源码内，即本仓库）：**
- 服务器指向地址
- 品牌痕迹（名称、包名、图标、吉祥物、文案）
- 隐藏五个配套端点入口

**不改的：**
- `packages/dsh_remote` 的协议代码（Noise IK 握手、载波、传输、server_api 之外的全部）——接受上游 wire 契约
- `runtime/`（引擎运行时、补丁、bridge、pins.json）
- `sdk/`（插件 SDK）
- 上游 ds-harness-remote 仓库（中继服务器软件）——**不改代码，只部署**
- 电脑端远程隧道插件（`@deepseek-ai/dsh-api-gateway`）——**不改，用户安装**

## 五、线上部署（改代码之外的线）

**1. 中继服务器（你的服务器）**
- 克隆 ds-harness-remote 仓库，按其文档把 **server 端**跑起来
- 绑 `真实域名（暂以 dsh.r2049.cn 占位）`、配 HTTPS 证书、数据库
- 版本落在兼容区间：plugin 0.6.2 / ds-harness-remote commit 479b943，端点白名单覆盖 0.5.17–0.6.0（对照上游核对）
- 它自带：登录、设备注册、配对、数据转发、网页控制台（`/app`）
- 不改它的代码，只部署

**2. 用户电脑（每个最终用户）**
- 装上游 DSH 引擎
- 装远程隧道插件 `@deepseek-ai/dsh-api-gateway`（市场已隐藏，手动安装）
- 插件里**填自己的中继地址 + 账号登录**——那台电脑才挂在自己服务器上，App 才能发现它
- 关键：配对二维码本身携带服务器地址（`device_pairing.dart:23`），登录也带 origin（`server_api.dart`），所以不是绑死上游，填谁挂谁

**3. APK 分发（你自己的）**
- `tooling/build-apk.sh --build-name <版本>` 出包
- 因包名已换，与原版不能覆盖安装，用户装的是全新 App
